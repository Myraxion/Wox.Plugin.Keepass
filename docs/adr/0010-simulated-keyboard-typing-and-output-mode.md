# Simulated Keyboard Typing, Stdin Execution, and Output Mode Adaptive Actions

To support anti-clipboard and credential auto-fill workflows securely, we introduce simulated keyboard typing alongside clipboard copying. Rather than executing keystroke payloads via shell arguments, typing payloads are strictly piped to native child processes over standard input (`stdin`). On Windows, keystroke text is sanitized against `System.Windows.Forms.SendKeys` control characters (`+^%~{}[]()`) and dispatched via hidden PowerShell; on macOS and Linux, raw text is streamed to `osascript` and `xdotool` respectively. This guarantees that passwords and sensitive tokens never hit process command-line telemetry, logs, or disk.

Typing actions first request Wox to hide via `api.HideApp` and wait 150ms to allow the active target window to regain input focus before sending keystrokes. A user-facing setting (`outputMode`: `clipboard` or `type`) configures the primary default Enter behavior (`IsDefault: true`). When set to `clipboard`, Enter copies the password while `mod+p` simulates typing; when set to `type`, Enter types the password while `mod+c` copies it. Secondary actions for username and TOTP seamlessly adapt their titles, icons, hotkeys, and underlying execution routines between clipboard and keystroke typing.

Action generation dynamically omits actions for absent fields (e.g., missing password, username, TOTP, or URL), preventing clutter. When an entry has no password, the default Enter action gracefully falls back to the first available non-empty field (such as username).
