# KeeWeb Relevance Scoring and Wox AutoScore Bypass

We replace hierarchical short-circuit sorting with a weighted sum model inspired by KeeWeb's 4-tier bidirectional string ranking (exact 10, prefix 5, substring 3, none 0). Field weights prioritize Title (10), URL (8), Tags (6), UserName (5), and Notes (2), combined with a low-weighted field completeness bonus (+2 for credentials: password/userName/otp, +1 for metadata: url/notes/tags, capped at +9) to break ties in favor of actionable credentials. Multi-word searches evaluate both holistic whole-query text and constituent tokens via dual-track scoring, strictly normalized to the [0, 100] closed range using rounding.

To ensure deterministic ordering in the desktop launcher UI, we declare `ignoreAutoScore` in `plugin.json` and bind persistent KeePass entry UUIDs to `Result.Id`. Wox's default `AutoScore` mechanism injects Fibonacci bonuses (+89 to +111 points) for previously executed entries, which completely eclipses relevance scores and ruins exact matches. Bypassing `AutoScore` and providing stable entry IDs prevents Wox from applying historical weights or resorting to random UUID tie-breaking jitter across keystrokes.
